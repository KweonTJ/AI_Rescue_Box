# AI Rescue Box — Project Context

## 0. 최우선 지침

- 전국 ICT 융합 공모전과 관련하여 이전에 기획했던 Go2 중심 구조 지도 생성, 매니퓰레이터, 다중 로봇 등의 기존 작품 기획은 모두 폐기한다.
- 이번 작품의 핵심 제품은 로봇이 아니라 **여러 탐사 플랫폼에 장착하거나 사람이 휴대할 수 있는 독립형 재난 지도 생성·전송 박스**다.
- 로봇개, 무한궤도 로봇, 이동 로봇 등은 AI Rescue Box를 운반하는 플랫폼일 뿐이며, 시스템의 핵심 기능은 특정 로봇에 종속되지 않게 구현한다.

---

## 1. 작품 기본 정보

### 작품명

**AI Rescue Box**

### 한 줄 정의

사전 건물 도면과 RGB-D SLAM을 결합해 재난 현장의 구조 대상자, 위험 구역, 통행 가능 구간과 구조 경로가 표시된 층별 2차원 구조 지도를 생성하고, 이를 압축하여 UWB로 베이스캠프에 전송하는 플랫폼 독립형 AI 재난 탐사 모듈이다.

### 핵심 목표

1. 통신 인프라가 불안정하거나 단절된 재난 현장에서 현장 지도를 생성한다.
2. 기존 건물 도면과 실제 재난 현장 지도를 비교하여 막힌 통로, 변경된 구조, 위험 구역을 갱신한다.
3. RGB-D 영상과 AI를 이용해 구조 대상자와 위험 요소의 위치를 지도에 표시한다.
4. 고용량 3차원 지도를 구조에 필요한 저용량 2차원 의미 지도로 변환한다.
5. 변환된 지도를 UWB로 베이스캠프에 전송한다.
6. 로봇개, 무한궤도 로봇, 이동 로봇, 사람 휴대 방식에 공통 적용한다.

---

## 2. 해결하려는 문제

재난 현장에서는 다음 문제가 동시에 발생한다.

- 기존 건물 도면과 실제 현장 구조가 붕괴물, 화재, 침수 등으로 달라진다.
- Wi-Fi, LTE, 5G 등의 통신 인프라를 사용할 수 없을 수 있다.
- 구조대가 내부에 직접 진입하기 전에는 구조 대상자와 위험 지점의 위치를 파악하기 어렵다.
- 3차원 포인트 클라우드 지도는 데이터가 커서 저속·불안정 통신으로 전송하기 어렵다.
- 단순 SLAM 지도만으로는 구조 대상자, 붕괴 위험, 낙상 위험, 통행 가능 여부를 직관적으로 판단하기 어렵다.

AI Rescue Box는 사전 도면, RGB-D SLAM, 객체·위험 탐지, 의미 지도 생성, 차원 축소, 압축, UWB 전송을 하나의 박스에서 수행한다.

## 3. 하드웨어 구성

| 하드웨어 | 역할 |
|---|---|
| Astra Depth Camera | RGB 영상과 깊이 영상 취득, RGB-D SLAM, 장애물·단차·구조 대상자 인식 입력 |
| Jetson Orin Nano 8GB | SLAM, AI 추론, 지도 정합, 의미 지도 생성, 3D→2D 변환, 경로 계획, 압축 수행 |
| ESP32 | Jetson과 UWB 모듈 사이의 통신 게이트웨이, 패킷 분할·재조립, 재전송, 상태 관리 |
| DWM1000 | 재난 현장 박스와 베이스캠프 사이의 UWB 데이터 송수신 |

### 외부 필수 장치

- 베이스캠프에는 별도의 DWM1000 수신기와 MCU 또는 USB 게이트웨이가 필요하다.
- 장착 플랫폼의 IMU 데이터를 ROS2 또는 직렬 통신으로 받을 수 있어야 한다.
- 사람이 박스를 들고 독립적으로 사용하는 모드까지 구현하려면 박스 내부에 소형 IMU를 추가해야 한다.

## 4. 전체 동작 흐름

1. **사전 지도 입력**
   - 건물의 2차원 평면도 또는 기존 점유 지도를 Jetson에 저장한다.
   - 도면을 SLAM 좌표계에서 사용할 수 있도록 크기, 방향, 원점, 층 정보를 정규화한다.

2. **현장 탐사 시작**
   - AI Rescue Box를 로봇개, 무한궤도 로봇, 이동 로봇에 장착하거나 사람이 휴대한다.
   - Astra Depth Camera로 RGB-D 데이터를 취득한다.

3. **RGB-D SLAM 및 위치 추정**
   - 깊이 영상과 RGB 영상을 이용해 현재 위치와 3차원 현장 지도를 생성한다.
   - 생성 중인 지도와 사전 도면을 정합하여 현재 위치와 구조 변화를 추정한다.

4. **AI 기반 의미 정보 추출**
   - 구조 대상자 위치를 탐지한다.
   - 막힌 통로, 잔해, 구멍, 급경사, 계단, 낙상·추락 위험 구간을 탐지한다.
   - 균열, 기울어짐, 변형 등 붕괴·파손 위험 징후가 있는 구역을 위험 후보로 표시한다.
   - 탐지 결과를 SLAM 좌표계로 변환하여 지도 위에 기록한다.

5. **지도 보정 및 누락 영역 추정**
   - 사전 도면과 관측된 SLAM 지도를 비교한다.
   - 깊이 센서의 사각지대 또는 일시적 관측 실패로 비어 있는 부분을 AI가 추정한다.
   - 실제 관측 영역과 AI 추정 영역을 반드시 분리하여 저장한다.
   - AI 추정 영역에는 신뢰도를 함께 기록하고, 구조대 화면에서 다른 표시로 보여준다.

6. **3차원 지도의 2차원 의미 지도 변환**
   - 3차원 포인트 클라우드 또는 복셀 지도를 층별 2차원 점유 지도로 투영한다.
   - 각 셀에 통행 가능, 장애물, 위험, 미관측, AI 추정 등의 상태를 기록한다.
   - 구조 대상자와 위험 요소를 별도의 의미 레이어로 저장한다.

7. **경로 생성**
   - 통행 가능 영역, 위험도, 장애물, 구조 대상자 위치를 기반으로 탐사 로봇 경로와 구조대 진입 경로를 생성한다.
   - 위험 구역은 높은 비용으로 설정하고, 통행 불가능 구역은 경로에서 제외한다.
   - 현장 변화가 발생하면 경로를 재계산한다.

8. **층 전환 판단 및 지도 전송**
   - 단순 IMU z축 값 하나만 사용하지 않는다.
   - 플랫폼 IMU의 수직 가속도, 자세 변화, SLAM의 높이 좌표 변화를 함께 사용해 계단 이동과 층 전환을 판단한다.
   - 층 전환이 확인되면 이전 층 지도를 스냅샷으로 확정하고 우선 전송한다.

9. **압축 및 UWB 전송**
   - 원본 3차원 포인트 클라우드는 UWB로 전송하지 않는다.
   - 층별 2차원 점유 지도, 의미 객체, 위험 정보, 경로, 신뢰도, 변경 영역만 전송한다.
   - 전체 지도 최초 전송 후에는 변경된 영역만 델타 방식으로 전송한다.
   - ESP32가 데이터를 DWM1000 프레임 크기에 맞게 분할하고 순번, CRC, 재전송 정보를 추가한다.

10. **베이스캠프 지도 복원**
    - 수신 패킷을 재조립하고 오류를 검사한다.
    - 압축된 지도를 복원한다.
    - 베이스캠프 AI가 누락 패킷 또는 저신뢰 영역을 추가 보정할 수 있다.
    - 실제 관측 정보와 AI 보정 정보는 끝까지 분리해서 표시한다.

## 5. 최종 출력 지도

베이스캠프 화면에는 다음 정보가 하나의 층별 구조 지도에 표시되어야 한다.

- 현재 탐사 위치
- 탐사 완료 영역
- 미탐사 영역
- 통행 가능 경로
- 통행 불가능 구간
- 구조 대상자 위치
- 붕괴·파손 위험 후보
- 낙상·추락 위험 구간
- 계단 및 층 연결 지점
- 구조대 추천 진입 경로
- 탐사 로봇 추천 이동 경로
- 실제 관측 영역
- AI 추정 영역
- 각 영역의 신뢰도
- 마지막 갱신 시각과 통신 상태

## 6. 핵심 기술 구성

### 6.1 사전 지도 정합

입력:

- 기존 2차원 평면도 또는 점유 지도
- RGB-D SLAM으로 생성된 현재 지도

출력:

- 사전 지도와 현재 지도의 좌표 변환
- 현재 위치
- 기존 구조와 달라진 영역
- 막힌 통로와 새로 열린 통로

초기 MVP에서는 수동 초기 위치 지정과 기하학적 정합을 사용하고, 이후 자동 정합 AI를 추가한다.

### 6.2 RGB-D SLAM

- Astra RGB 영상과 깊이 영상을 사용한다.
- 6-DoF 위치 추정과 3차원 현장 지도를 생성한다.
- 로봇 종류와 관계없이 카메라 좌표계와 박스 기준 좌표계만 고정한다.
- 초기 구현은 검증된 RGB-D SLAM 패키지를 이용하고, 전체 SLAM 알고리즘을 처음부터 개발하지 않는다.

### 6.3 AI 위험·객체 탐지

탐지 클래스 예시:

- 구조 대상자
- 잔해 및 통로 차단물
- 구멍 및 낙하 위험
- 급경사 및 단차
- 계단
- 균열·변형 등 붕괴 위험 징후

주의:

- 단일 RGB-D 카메라만으로 실제 붕괴 시점을 정확히 예측한다고 표현하지 않는다.
- 작품 설명에서는 **붕괴·파손 위험 징후 탐지 및 위험 후보 표시**라고 정의한다.

### 6.4 AI 지도 완성

입력 채널 예시:

- 사전 점유 지도
- 현재 관측 점유 지도
- 관측 마스크
- 장애물·위험 의미 레이어

출력:

- 누락 영역에 대한 추정 점유 지도
- 셀별 신뢰도
- 관측 영역과 추정 영역 구분 마스크

안전 규칙:

- AI는 실제 관측 셀을 덮어쓰지 않는다.
- AI 추정 결과를 확정 정보처럼 표시하지 않는다.
- 경로 계획에서는 저신뢰 추정 영역에 추가 비용을 부여한다.

### 6.5 3D→2D 차원 축소

- 3차원 지도에서 바닥 높이 기준으로 층을 분리한다.
- 구조대 이동 가능 높이 범위의 장애물을 2차원 점유 셀로 투영한다.
- 머리 위 구조물, 바닥 장애물, 낙하 위험을 별도 레이어로 유지한다.
- 구조에 필요하지 않은 원본 포인트는 전송 데이터에서 제외한다.

### 6.6 UWB 전송

전송 대상:

- 지도 메타데이터
- 층 ID
- 점유 지도 또는 변경 패치
- 구조 대상자·위험 객체 목록
- 추천 경로
- 관측·추정 마스크
- 신뢰도
- 타임스탬프

전송하지 않는 대상:

- 원본 RGB 영상 전체
- 원본 깊이 영상 전체
- 원본 3차원 포인트 클라우드 전체

통신 요구사항:

- 패킷 순번
- 지도 버전
- 층 ID
- 전체 패킷 수
- CRC
- ACK/NACK
- 누락 패킷 선택 재전송
- 중복 패킷 제거
- 전송 중단 후 이어받기

## 8. ROS2 기준 소프트웨어 모듈

권장 기준:

- Ubuntu 22.04
- ROS2 Humble
- Jetson: AI 추론 및 지도 처리
- ESP32: UWB 통신 펌웨어
- AI 프로토타입은 Python, 성능이 필요한 지도·통신 모듈은 C++로 구현

### Jetson 노드

| 노드 | 역할 |
|---|---|
| `astra_driver_node` | RGB·Depth 프레임 입력 |
| `rgbd_slam_node` | 위치 추정 및 3차원 지도 생성 |
| `prior_map_loader_node` | 사전 지도 로드·정규화 |
| `map_registration_node` | 사전 지도와 현재 지도 정합 |
| `semantic_detector_node` | 구조 대상자·위험 요소 탐지 |
| `semantic_fusion_node` | 탐지 결과를 지도 좌표계에 누적 |
| `map_completion_node` | 누락 영역 AI 추정 및 신뢰도 생성 |
| `semantic_2d_map_node` | 층별 2차원 의미 지도 생성 |
| `route_planner_node` | 탐사·구조 경로 생성 |
| `floor_transition_node` | IMU와 SLAM 높이 기반 층 전환 판단 |
| `map_compressor_node` | 지도 압축 및 델타 패치 생성 |
| `uwb_gateway_node` | ESP32로 전송할 데이터 직렬화 |

### ESP32 펌웨어

| 모듈 | 역할 |
|---|---|
| `jetson_link` | USB/UART로 Jetson 데이터 수신 |
| `packetizer` | UWB 프레임 단위 분할 |
| `uwb_transport` | DWM1000 송수신 |
| `retransmission` | ACK/NACK 및 누락 패킷 재전송 |
| `status_reporter` | 통신 상태와 전송 진행률 반환 |

### 베이스캠프 모듈

| 모듈 | 역할 |
|---|---|
| `uwb_receiver` | UWB 패킷 수신 |

## 11. MVP 범위

1차 시제품에서 반드시 구현할 기능:

1. Astra RGB-D 입력
2. RGB-D SLAM 및 현재 위치 표시
3. 사전 2차원 지도 불러오기
4. 사전 지도와 SLAM 지도 수동 또는 반자동 정합
5. 구조 대상자와 장애물 최소 2종 탐지
6. 3차원 지도에서 2차원 점유 지도 생성
7. 지도에 구조 대상자와 장애물 위치 표시
8. A* 기반 탐사 또는 구조 경로 생성
9. 지도 압축 및 파일 단위 복원 검증
10. Jetson→ESP32→DWM1000→베이스캠프 전송
11. 패킷 손실 시 재전송
12. 층별 지도 스냅샷 저장과 전송

14. 베이스캠프 UI에서 지도와 경로 표시

## 14. 시연 시나리오

1. 붕괴 전 건물의 2차원 평면도를 AI Rescue Box에 입력한다.
2. 박스를 무한궤도 로봇 또는 사람이 운반하며 모의 재난 현장에 진입한다.
3. 현장에는 마네킹 구조 대상자, 막힌 통로, 잔해, 낙상 위험 구간을 배치한다.
4. Astra RGB-D와 SLAM으로 현장 지도를 생성한다.
5. 사전 도면과 실제 지도를 비교하여 변경 구역을 표시한다.
6. AI가 구조 대상자와 위험 요소를 탐지해 지도에 표시한다.
7. 시스템이 안전 비용을 반영한 진입 경로를 생성한다.
8. 3차원 지도를 층별 2차원 의미 지도로 변환하고 압축한다.
9. 압축 지도를 UWB로 베이스캠프에 전송한다.
10. 베이스캠프 화면에서 구조 대상자, 위험 구역, 실제 관측 영역, AI 추정 영역, 추천 경로를 확인한다.
11. 계단 이동 또는 층 전환이 검출되면 이전 층 지도가 자동 확정·전송되는 것을 시연한다.

## 15. 차별성

- 특정 로봇을 개발하는 것이 아니라 기존 탐사 로봇에 장착할 수 있는 공통 구조 인지 모듈이다.
- 사전 건물 도면과 실시간 RGB-D SLAM을 결합해 재난 전후 구조 변화를 표시한다.
- 단순 점유 지도가 아니라 구조 대상자, 위험 요소, 경로가 결합된 의미 지도를 생성한다.
- 고용량 3차원 데이터를 저용량 2차원 구조 정보로 변환하여 통신 부담을 줄인다.
- 일반 통신 인프라 대신 UWB 기반 독립 통신 경로를 사용한다.
- 실제 관측 정보와 AI 추정 정보를 분리해 AI 환각으로 인한 안전 문제를 줄인다.
- 로봇 장착과 사람 휴대 방식을 모두 지원한다.

## 16. Codex 작업 규칙

- 기존 ICT 공모전 기획의 코드와 문서를 자동으로 재사용하지 않는다.
- Go2, 매니퓰레이터, 강화학습 보행 제어는 AI Rescue Box의 핵심 범위가 아니다.
- 특정 로봇 제어 코드는 `platform_adapter` 계층 외부로 침투시키지 않는다.
- 기능을 한 번에 구현하지 말고 입력, 지도, AI, 압축, 통신, UI를 독립 모듈로 작성한다.
- 하드웨어가 없어도 ROS2 bag과 모의 데이터로 각 모듈을 테스트할 수 있어야 한다.
- UWB 연결 전에는 파일 및 가상 직렬 링크로 패킷화·복원 시험을 먼저 수행한다.
- 원본 관측 정보와 AI 추정 정보는 데이터 구조와 UI에서 항상 구분한다.
- AI 추정값을 실제 관측값으로 덮어쓰지 않는다.
- 모든 패킷과 지도에는 버전, 층 ID, 시간, 좌표계 정보를 포함한다.
- 구현을 수정할 때 README, 아키텍처 문서, 실행 명령, 테스트 방법을 함께 갱신한다.
- 임의의 하드웨어 핀, 포트, 토픽 이름을 확정하지 말고 설정 파일로 분리한다.
- 불확실한 기능을 완성된 기능처럼 문서화하지 않는다.
